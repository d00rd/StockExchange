# Stock Exchange

A Java 23 stock exchange implemented as a TCP server with Swing clients and a multi-threaded concurrent market simulator. Buyers submit requests, sellers submit offers, and the server matches compatible orders while broadcasting the public order book, trade history, and account updates to connected clients.

## Concurrency Requirements & Features

> **Academic Specification:**
> *"The programs are local Java applications that implement the main logic specific to the chosen theme. They use synchronization mechanisms to ensure data integrity. Clients that arrive concurrently are simulated using threads."*

### Key Highlights
1. **Four Concurrency Cases (SAFE vs UNSAFE comparison)**:
   - Case 1: Price lock during purchase (racing against order modification).
   - Case 2: Two buyers racing for the same shares (preventing overselling / double execution).
   - Case 3: $X + Y > \text{Available}$ requested shares (atomic partial fills).
   - Case 4: Account double-spending / overdraft prevention (atomic reservation under `Account.lock` vs unsafe TOCTOU).
   - *Full details and benchmarks in [CONCURRENCY.md](CONCURRENCY.md).*
2. **Synchronized Financial Accounts & Portfolios**:
   - Every trader has an account with ledger cash, reserved cash, share holdings, and reserved shares.
   - **Canonical Lock Ordering**: bilateral settlements lock buyer and seller accounts in alphabetical order of trader ID, mathematically preventing circular-wait deadlocks.
3. **Multi-Threaded Market Simulator (`MarketSimulator`)**:
   - Clients arriving concurrently are simulated using Java platform threads.
   - Simulates diverse trading behavior (limit orders, takes, modifications, cancellations) released simultaneously with a `CyclicBarrier`.
   - Continuous background invariant auditor asserting mathematical conservation of money and stock.
4. **Swing Client UI**:
   - Interactive terminal showing live order books, transaction history, and personal portfolio (available cash, reserved cash, shares).
   - Includes one-click deposit and a "Start Bot Traders" control to spawn live background client threads directly into the exchange.

## Project Structure

- `src/main/java/org/example/Main.java`: selects `server`, `client`, or `simulate` mode.
- `src/main/java/org/example/exchange/`: matching engine. `StockExchange` serializes operations per symbol via `OrderBook` locks.
- `src/main/java/org/example/account/`: synchronized balance reservations, portfolio tracking, and deadlock-free bilateral settlements (`Account`, `AccountManager`, `AccountSnapshot`).
- `src/main/java/org/example/simulation/`: multi-threaded client arrival simulation and real-time financial invariant auditing (`MarketSimulator`, `SimulationReport`).
- `src/main/java/org/example/protocol/Protocol.java`: line-oriented TCP protocol (orders, trades, symbols, portfolio, deposit).
- `src/main/java/org/example/server/`: TCP server using virtual threads per client session (`ExchangeServer`, `ClientSession`).
- `src/main/java/org/example/client/ExchangeClient.java`: asynchronous TCP client. `ClientUI.java` is the Swing GUI.
- `src/test/java/org/example/`: 39 unit, concurrency, deadlock, and simulation tests.

## Concurrency and Operation Safety

### 1. Exchange Order Books
Each company symbol has its own fair `ReentrantLock` in `OrderBook`. Unrelated stocks trade concurrently in parallel, while operations on the same stock are serialized.
- Timed `tryLock` on order modification and cancellation prevents indefinite blocking.
- Deadlock-free subscriptions lock books in a consistent alphabetical order.
- Unique atomic IDs generated by independent `AtomicLong` counters.

### 2. Account Balances and Deadlock Prevention
- **Double-Entry Reservation**:
  - $\text{availableCash} = \text{cash} - \text{reservedCash}$
  - $\text{availableShares} = \text{holdings} - \text{reservedHoldings}$
  - When placing buy/sell orders, funds or shares are reserved atomically under `Account.lock`.
- **Canonical Lock Ordering in Bilateral Settlement**:
  - Trades involve two distinct accounts: Buyer and Seller.
  - To prevent deadlock when Trader A trades with Trader B while Trader B trades with Trader A, `AccountManager.settleTrade` orders lock acquisition lexicographically (`traderA.compareTo(traderB) < 0`).
- **Hierarchy of Locks**:
  - The lock hierarchy strictly requires acquiring `OrderBook.lock` before any `Account.lock`. No code path ever requests an `OrderBook.lock` while holding an `Account.lock`, preventing cross-resource deadlocks.

### 3. Server and Networking
- Every TCP connection is handled by a virtual thread.
- `LinkedBlockingQueue` outbox decouples exchange order matching from network I/O, protecting locks from slow clients.
- `AtomicBoolean.compareAndSet` ensures idempotent session cleanup.

## Tests

Run the full test suite with Maven:
```powershell
mvn test
```

Runs **39 JUnit tests** across 6 test classes:
- `ConcurrencyCasesTest`: 200 rounds each for Cases 1, 2, and 3 in SAFE vs UNSAFE mode.
- `AccountConcurrencyTest`: tests safe vs unsafe double-spending and high-concurrency bilateral settlements (16 threads, 16,000 trades) asserting zero deadlocks and 100% money/share conservation.
- `AccountManagerTest`: balance deposits, reservations, price improvement refunds, and insufficient funds rejections.
- `MarketSimulatorTest`: tests multi-threaded client arrival simulation with continuous invariant auditing.
- `StockExchangeConcurrencyTest`: barrier-synchronized races (two buyers, partial offers, cancel-vs-buy, modify-vs-buy, 16-thread stress test).
- `StockExchangeTest`: core matching logic, price/time priority, execution price rules.
- `ExchangeServerIntegrationTest`: real network TCP clients talking to a live server.

## Build and Run

Requires JDK 23 and Maven.

```powershell
mvn clean package
```

### 1. Run the Concurrent Market Simulator (CLI)

Simulate concurrent clients arriving and trading:

```powershell
# Syntax: simulate [numClients] [durationSeconds] [safe|unsafe] [settlementDelayMs]
java -cp target/stock-exchange-1.0-SNAPSHOT.jar org.example.Main simulate 8 3 safe
```

Run in `unsafe` mode to observe concurrency violations caught by the auditor:
```powershell
java -cp target/stock-exchange-1.0-SNAPSHOT.jar org.example.Main simulate 8 3 unsafe 2
```

### 2. Run the TCP Server

Default port is 5000:
```powershell
java -cp target/stock-exchange-1.0-SNAPSHOT.jar org.example.Main server 5000
```

### 3. Run Swing Clients

In separate terminals:
```powershell
java -cp target/stock-exchange-1.0-SNAPSHOT.jar org.example.Main client localhost 5000 alice
java -cp target/stock-exchange-1.0-SNAPSHOT.jar org.example.Main client localhost 5000 bob
```
- The GUI displays personal cash balances, reserved funds, and stock holdings.
- Click **Start 3 Bot Traders** in the UI to launch live simulated client threads that populate the order book and trade in real-time.
